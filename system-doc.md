# Tech Spec

## Implementation Overview
`FogCameraManager` owns the normalized maze-space current-visibility texture, ping-pong explored-history texture, fog-derived wall knowledge, render-mask outputs, and their demand-driven update lifecycle. PGO-97 replaces only the current-visibility generator: the retired 3D camera/light/fog-mesh capture is now an isolated, 2D-only `SubViewport` containing a black background, a white light-only receiver, component-owned `PointLight2D` reveal lights, and topology-derived `LightOccluder2D` geometry. PGO-116 removes `FogRevealSource3D` entirely; `FogRevealSource2D` is now the sole reveal-source class, and the manager no longer creates or owns any reveal light itself.

- Current visibility remains a black-to-white `Texture2D`, mapped from maze-local X/Z to capture X/Y. Its bounds extend half a configured 3D wall thickness outside the cell grid on every edge, matching the wall-inclusive 2D projection textures and 3D maze footprint. Downstream history merging, wall-watch UVs, material sampling, discovery, and render-mask composition use that same explicit capture rectangle.
- `FogRevealSource2D` owns its own capture light outright; the manager only reparents that light into the isolated capture canvas and mirrors its transform (`_adopt_2d_source_capture_light()` / `_update_2d_source_capture_light()`). `register_reveal_source()` rejects anything that is not a `FogRevealSource2D` — there is no other renderer-neutral source type and no manager-owned proxy path to fall back to.
- PGO-277 binds the shipped player's `FogRevealSource2D` to `level_state/player_sight_distance` through the scene-authored `range_state_path`. The component caches the resolved numeric range, updates its owned `PointLight2D.texture_scale`, and emits one `source_changed` only when that effective range changes. `FogCameraManager` keeps its existing ownership boundary: it mirrors the component-owned light, queues old/new footprints, invalidates current visibility, and schedules a single demand-driven capture without owning a second range authority.
- `FogRevealSource2D` reveals from the owning entity's `EntityInfo` detection origin rather than from its own transform. Entity prefabs author the revealer as a sibling of the `CharacterBody2D` that moves, so a revealer that read its own `global_position` would stay parked at the spawn cell for the entity's whole life. An explicit `origin_node` overrides the resolved origin; a source with neither tracked origin keeps revealing from itself and never processes.
- Reveal-source registration is a lifecycle fact, not a rendering one: a source registers from `_ready()` regardless of its own or any ancestor's `visible` flag, because the 2D world that owns the authoritative sources is itself never presented directly. A revealer authored inside hidden scratch content therefore still reveals, invisibly to whoever hid it, which is why no such content may carry one.
- The gameplay 2D maze space is authored in pixels while the capture canvas is authored in maze world units. Every 2D-authored contribution added to `_capture_root_2d` — reveal-light positions as much as wall occluder geometry — converts through the single `_maze_pixels_to_world_scale()` authority. Mixing the two spaces places a light `cell_size_px` times too far from the maze origin, which reads as a maze that is entirely dark.
- Static walls, destruction intervals, and dynamic render-segment providers produce independently replaceable 2D occluders. Unknown walls still occlude; wall knowledge is never used as blocker input. Axis-aligned dynamic panel thickness extends only perpendicular to each segment, preserving authored endpoint gaps such as a sliding door's visibility-only peek opening.
- Explored history continues to merge as `max(current_visibility, previous_history * retention)`. Dirty-region publication, `fog_history_surface_updated`, PGO-40 wall knowledge, and PGO-89 composable masks are unchanged consumers of the migrated current surface.
- PGO-157 replaces radial memory decay with age-ordered forgetting. The history texture's `.g` channel carries recency: `1.0` is "seen this pass" and lower values are older. Each history advance multiplies retained recency by `i / (i + 1)` for step count `i`, so the newest memory stays at `1.0` and older memory spreads evenly toward `0.0` without colliding. A single global `forget_threshold` walks up through that gradient and erases everything below it, which forgets the oldest explored areas first regardless of where they sit in the maze. Every other channel (`.r`/`.b`/`.a`) still carries the explored mask that all downstream consumers sample.
- Settled-frame housekeeping is event-driven. Scene structure invalidation listens to `SceneTree.node_added`/`node_removed` and filters for visibility-material nodes or dynamic segment providers; animated sprite texture changes arrive from `frame_changed`/`animation_changed`. The manager must not use broad `tree_changed` invalidation or poll stable material textures every frame.
- PGO-101 replaces PGO-100's `MaskPostPassChain` square max/min post-pass with a `RenderingDevice` compute ping-pong simulation, `OrganicVisibilityMaskSimulation`. PGO-100's shader and its texel-space `growth_speed`/`shrink_speed` state variables are retired outright rather than kept selectable. The simulation is still presentation-only: `is_maze_cell_currently_visible(cell)`, wall knowledge, cell discovery, fog history, AI and placement all keep reading the unanimated composed surfaces. It also still has exactly one producer, but its output is no longer delivered to exactly one material -- see the derived render masks below.
- The simulation's field reaches consumers as an ordinary render mask, not as a post-composition texture swap. `RENDER_MASK_NAMES` carries two derived masks alongside the four captured ones: `game_world` is the raw captured `game_world` composite, and `game_world_animated` is that field after the simulation. The default matrix routes raw `game_world` to `game_floor`, so captured world-mask contributions apply at the in-game render-texture boundary. The 3D world does not reuse that 2D routing entry: its floor, wall, and maze-object materials resolve only `game_world_animated` at their material boundary.
- PGO-307 routes the resolved camera-room texture through that same substrate boundary. `FogCameraManager` retains ownership of the per-room textures and blends its transition `from`/`to` textures in the `camera_rooms` composite viewport; `MazeCameraManager` claims that mask as a multiplicative direct-runtime contribution to raw `game_world` only while camera-room mode is active. A blend invalidates the camera-room composite and therefore the `game_world` input consumed by the simulation. The 3D overlay and source-material bindings then resolve only `game_world_animated`, including its raw passthrough, while `fog_world_mask_3d.gdshader` samples only `mask_tex` and has no camera-room uniforms or second multiplication branch. Existing 2D camera-room consumers remain on their established bindings.
- `game_world_animated` is an exact texture-object passthrough of `game_world` whenever the simulation is disabled, has no `RenderingDevice`, or is still withholding its first presented frame, so 3D world objects never go dark when animation is toggled off or unavailable. `is_presenting()` is the single predicate both the texture accessor and the published revision agree on.
- "Disabled is an exact presentation bypass" includes the resources, in both directions. Setting `enabled` false detaches and frees the simulation owner and its packed auxiliary capture; it does not leave a dormant `RenderingDevice` allocation and `SubViewport` behind. `remove_child` runs their `_exit_tree` GPU teardown synchronously so a lookup on the same frame is truthful, while the objects themselves are destroyed on the deferred queue so a dispatch recorded this frame is never freed under the render thread. A test asserting the disabled invariant must therefore *claim* the disabled state rather than infer it from the shipped default, which is an authored look value and is currently `true`.
- A derived mask owns no capture surface. It therefore binds no `pixels_per_cel` -- `game_world` inherits the capture viewport and `game_world_animated`'s density is `simulation_pixels_per_cell` -- and it is refused on the captured `game_world` target, because that composite is precisely what the derived masks republish and contributing back into it would feed the simulation its own output.
- Mask composition is ordered substrate → simulation → render layers. A flat pass over `RENDER_MASK_TARGETS` cannot express this: `game_world` sorts last and the simulation ran after the whole pass, so any layer routed to a derived mask sampled a field two hops stale.
- `game_world_animated` publishes its own monotonic revision rather than forwarding whichever source it is presenting from. The substrate revision and the simulation's dispatch count are independent counters, so a passthrough/presenting transition could land on the same number twice and read as "unchanged" while the texture changed.
- The compositor carries four mask slots. Six mask names are registered, so a target given more than four active masks silently drops the extras; routing a layer to a derived mask is meant to REPLACE the captured masks on that layer, not stack on them. The manager warns once per over-subscribed target rather than composing a quietly wrong picture.
- The simulation owns two state lanes per concept. A blocker-aware NORMAL lane and an occlusion-bypass lane are simulated independently and resolved as `max(normal, bypass)` at presentation, so an `occlusion_enabled = false` source can cross a blocker without granting that ability to any other source. Each lane carries a continuous phase field (organic boundary, curvature smoothing, halo, retraction) and a discrete creep claim (guaranteed propagation and complete thin-feature fill).
- Growth ADVANCES a front, it never creates one. The phase kernel applies its growth bias only where the renormalised neighbourhood is non-zero. Without that gate the operator self-nucleates whenever the bias exceeds `0.5 * (sharpness - 1)`, every permitted texel lights up unprompted, and seeds, creep and islands all become meaningless. The gate also bounds the front at one simulation texel per tick by construction.
- The halo is bounded structurally, not by decay. A separable two-pass L1 ramp produces `support(p) = max over substrate q of (1 - L1(p, q) / radius)`, and the phase field is clamped by it outside the substrate, so no halo texel can be non-zero past `halo_radius_cells` at any tick count.
- Simulation state is a pure function of the executed TICK count. Ticks are derived from total elapsed simulation time and creep substeps are metered per tick rather than per frame, so 30, 60 and 144 rendered FPS execute an identical tick-for-tick sequence. Catch-up is capped and the backlog is DROPPED rather than worked off, so a hitch costs simulation time instead of compounding into a frame spiral.
- No per-frame GPU-to-CPU readback exists anywhere in the continuous path. The only readback is inside the manual island-seeding command, which the Goal explicitly carves out; the simulation counts every readback it performs so the constraint is measurable rather than merely reviewed.

## Key Files and Interfaces

- `systems/maze/fog_camera_manager.gd` (`FogCameraManager`) owns `SURFACE_CURRENT_VISIBILITY` and `SURFACE_FOG_OF_WAR`, the isolated capture graph, occluder caches, history viewports, mask compositor, wall-knowledge controller, and debug snapshots. `get_current_texture()`, `get_fog_of_war_texture()`, and `get_seen_texture()` preserve the texture APIs. `is_maze_cell_currently_visible(cell)` is a conservative, non-occluding CPU fact query over `FogRevealSource2D` volumes (converted from maze pixels to world units) and never samples a texture.
- `systems/perception/fog_reveal_source_2d.gd` (`FogRevealSource2D`) registers in `_ready()`, unregisters in `_exit_tree()`, and emits `source_changed` for transform, authored, resolved-range, and gameplay-state changes. It creates and configures its own `PointLight2D`; the manager only reparents that light into the capture canvas and mirrors its transform. Its public source data is `is_effectively_enabled()`, `get_effective_origin()`, `get_effective_forward()`, `get_effective_range()`, `shape`, `cone_angle_degrees`, and `occlusion_enabled` — the same renderer-neutral contract `FogRevealSource3D` used to expose. `get_effective_origin()` resolves `origin_node`, then the sibling `EntityInfo` detection origin, then this node's own position. Because a `Node2D` origin has no transform signal, movement is polled in `_physics_process`, matching how `EntityInfo` refreshes its own query-index position; the notification-driven and polled paths both gate on an actual position/rotation change; a rewritten-but-unchanged transform must not re-emit `source_changed`.
- `data/entities/player/player_2d.tscn` keeps `FogRevealSource2D.range_state_path = "level_state/player_sight_distance"` as the production configuration. `FogRevealSource2D` binds the current `StateVariable` at that normalized path, falls back to its authored `reveal_range` for a missing or non-numeric value, disconnects the old instance before a rebind, and disconnects both the variable and StateStore listeners on teardown.
- `systems/autoload/state_store.gd` and `systems/state/state_machine_runtime.gd` expose `variable_instance_replaced(variable_path, previous_variable, replacement_variable)`. This is a registry-identity event only: ordinary claims, overrides, and default restoration continue through `StateVariable.resolved_value_changed`. StateStore rewires its own observers before forwarding the runtime event, so cached consumers can abandon a stale variable instance safely.
- `systems/maze/fog_memory_decay_controller.gd`, `fog_memory_decay_source_3d.gd`, `fog_memory_decay_config.gd`, `fog_memory_dissolve_profile.gd`, and `rendering/fog_history_merge.gdshader` retain the priority-arbitrated, one-shot scheduled history-decay contract. Because forgetting is now ordered by age rather than distance, the winning tier's contributions collapse to a single frontier: the controller exposes `get_pending_frontier_advance()` (fastest winning rate x cadence) and `get_frontier_soft_edge()`, and the shader takes one `forget_threshold`/`forget_soft_edge` pair instead of a 64-entry origin/radius array. `FogMemoryDecaySource3D` no longer has a decay origin and does not react to its own transform.
- `systems/maze/maze_wall_knowledge_2d.gd`, `maze_wall_watch_descriptors.gd`, `maze_wall_watch_reducer.gd`, and `rendering/maze_wall_watch_reducer.gdshader` consume only the history texture and unchanged `fog_history_surface_updated(dirty_uv_rects)` timing; see `systems/maze-wall-knowledge-tech-spec.md`.
- `scenes/maze/MazeMain.tscn` composes the manager, the two history viewports, and `FogMemoryDecayController`. The current viewport is configured at runtime as a 2D-only capture surface.
- `systems/maze/organic_visibility_mask_simulation.gd` (`OrganicVisibilityMaskSimulation`) owns every compute resource: five pipelines built from `rendering/compute/visibility_mask_{pack,halo,phase,creep,present}.glsl`, the packed input image, the halo pair, the two ping-ponged `RGBA16F` state images, and the single `Texture2DRD` present image the materials bind. All recording happens inside one `RenderingServer.call_on_render_thread` callback per frame, in order: pack (only when the input revision changed), halo, then per tick one phase dispatch followed by that tick's ordered creep substeps, then present. Ping-pong is internal, so the published texture object is stable and a transition can never expose a half-written buffer.
- `systems/maze/organic_visibility_mask_scheduler.gd` (`OrganicVisibilityMaskScheduler`) is a deliberately Node-free, GPU-free object so the frame-rate equivalence requirement can be proven by arithmetic. `simulate_run(...)` replays a whole run at a fixed frame rate and reports the tick total and the per-tick creep sequence.
- `systems/maze/packed_visibility_capture.gd` (`PackedVisibilityCapture`) owns the packed auxiliary capture: `R` normal reveal seed, `G` occlusion-bypass reveal seed, `B` fog blocker geometry. It is a plain unshaded additive paint at the current-visibility capture's size over the same wall-inclusive maze rect, redrawn only when a source moves, is suppressed, or a blocker's geometry revision changes. Blockers are painted from `FogBlocker2D.get_polygon()` — the same polygon the component hands its `LightOccluder2D` — so the blocker representation and the occluder cannot drift apart. It is a separate surface from the current-visibility capture because that capture's reveal lights write all of RGB and its alpha is already the PGO-157 explored-memory lane; recolouring the lights would still leave only two free channels for three lanes while putting a gameplay-critical surface at risk.
- `FogCameraManager` creates the simulation and the packed capture on demand through `_ensure_visibility_mask_simulation()`, drives both every `_process(delta)` through `_update_visibility_mask_simulation_if_needed(delta)`, routes raw `game_world` through the render-layer compositor to the captured `game_floor` texture, and resolves only `game_world_animated` inside `_update_source_visibility_materials()` and `_update_mask_textures()` for 3D floor, wall, maze-object, and world-overlay materials. Its camera-room composite viewport is the one transition-aware `camera_rooms` texture source; it republishes the blend as a normal render-mask contribution instead of supplying it to any 3D material directly. `shared/state/shared_state_keys.gd` defines the two derived mask names, `ANIMATED_VISIBILITY_MASK_ROOT`, the fifteen leaf paths, and `ANIMATED_VISIBILITY_MASK_CONFIG_LEAVES`, which is the bind order the manager hands the simulation as one dictionary.
- `systems/state/state_path_aliases.gd` migrates schema-2 BASE and override entries from every retired `render_masks/{ingame,ingame_animated}/<target>` path to its `render_masks/{game_world,game_world_animated}/<target>` successor. These are persistence aliases only: the retired names are not registered as live StateStore variables, render-texture widgets, or runtime mask names.

## State, Lifecycle, and Data Flow

1. A reveal source resolves the manager once, registers, and causes the manager to create/update its proxy and cache a conservative UV footprint. Missing a manager uses a one-shot `SceneTree.node_added` handoff rather than polling.
2. Source movement, rotation, range, shape, occlusion, enablement, registration, removal, capture layout changes, and relevant topology changes invalidate current visibility. Old and new source footprints are queued for history; topology queues full UV. A removed or disabled source clears only live visibility and does not erase explored memory.
3. For a state-backed range, the source first applies the current resolved numeric value, then listens to that variable's `resolved_value_changed`. An actual numeric effective-range transition updates the owned capture light and emits exactly one source event; an unchanged resolved value is a no-op and creates no capture invalidation or redraw. On `variable_instance_replaced` for its normalized path, the source disconnects the prior variable, adopts the replacement's current value immediately, and ignores later emissions from the stale instance. Claim removal and default restoration remain ordinary resolved-value transitions on the live variable.
4. The manager refreshes capture geometry, static occluders, changed dynamic-provider occluders, source proxies, material bindings, and wall-knowledge view bindings only when their explicit dirty state requires it. Once both real maze views are bound, the wall-knowledge controller is not reconfigured each frame. A pure world rotation of the maze updates world-to-maze material uniforms but does not invalidate the maze-local capture.
5. A consumed dirty current surface receives one `UPDATE_ONCE`; if history must advance, the manager merges current and previous textures, emits coalesced dirty UV regions, and hands them to wall-watch reduction. Unchanged frames request no capture redraw, registry scan, occluder rebuild, or full-texture readback.
6. Reset or non-preserving maze replacement clears history, rewinds the recency step counter, and rewinds the forget frontier to `0.0`. Disabling every contribution stops the frontier where it is rather than rewinding it, so already-forgotten memory stays forgotten and a re-enabled pill resumes from where it left off. Preserving refresh retains registrations and history but publishes full UV so descriptor-indexed wall knowledge re-evaluates after remapping. Teardown disconnects source/decay signals and frees proxies, occluders, reducers, and viewport resources.
7. The animated mask post-pass seeds from the current composed `game_world` mask when the feature is enabled, on a non-preserving `_apply_maze_state()` (history actually reset or the capture resized), and on player teleport; the latter two defer seeding to the next composed revision (`seed_on_next_input_revision()`) instead of seeding from a stale pre-transition texture. A same-layout preserving refresh — `refresh_runtime_maze()` with history and wall state preserved, such as wall destruction — is an input revision rather than a simulation lifecycle boundary: it does not reseed, so the simulation's GPU state and scheduler tick count keep advancing and convergence continues from the presented field toward the remapped `game_world` target instead of restarting from a cleared substrate. `set_maze()` (full/non-preserving maze application) and explicit teleport still reseed unconditionally. Once seeded, `update(...)` compares the composed mask's revision counter to detect a new growth/shrink target; growth is optionally biased outward from the player's camera-target UV footprint (`_update_animated_mask_growth_seed()`) rather than growing uniformly from the seeded frame. A fog-of-war reset bumps that surface's render-mask revision (`_bump_render_mask_texture_revision(SURFACE_FOG_OF_WAR)`) so a reset target that leaves the raw current-visibility surface unchanged still restarts animated convergence toward the reset target. Growth and shrink accumulate against the same delta-clamped simulation clock (`MAX_DELTA_SECONDS` per frame) that also bounds idle-convergence. A queued ping-pong viewport is promoted to the presented output only after it has completed one full rendered frame.

## Invariants and Failure Modes

- There is one production current-visibility backend: the 2D capture graph. The legacy 3D fog camera, remote anchor, fog-only 3D layers/meshes, shared `World3D` binding, fog-only source lights, and `FogRevealSource3D`/`RevealerLight3D` themselves are absent. `FogRevealSource2D` is the only reveal-source class; `register_reveal_source()` rejects any other node type outright rather than falling back to a manager-owned proxy.
- Capture content is isolated by dedicated light and occluder masks; ordinary presentation nodes cannot contaminate its normalized mask. Empty capture is black.
- Maze-local mapping is explicit through `_capture_rect_2d`; all consumers use the same X/Z-to-UV contract. `_wall_inclusive_maze_rect()` is the shared authority for the capture texture size, light-only receiver, source/occluder canvas transform, and camera-room rasterization. The capture target adds one full wall thickness to each cell-grid dimension (half on each opposing edge), using `capture_resolution_per_grid_square / cell_size` to preserve world scale. Source motion relative to the maze still changes capture, while presentation-only maze rotation does not.
- Occluders derive from authoritative topology and dynamic-provider revisions. A local provider revision rebuilds only that provider; destroyed wall spans no longer occlude; a stale proxy or occluder after replacement/teardown is a defect. Dynamic door panels must not grow thickness caps past their authored endpoints, because overlapping caps would silently close valid narrow visibility gaps.
- A stable scene must not cause dynamic-provider registry scans, visibility-material rebinding, sprite texture polling, or wall-knowledge controller reconfiguration. Late-added and removed providers, geometry, sprites, and maze views must still invalidate their relevant caches.
- The manager never calls `get_image()` on current visibility or fog history. Wall-watch readback is limited to its candidate-sized reduction target.
- History is internally consumed whenever a maze has a reveal source or decay contribution, independently of render-mask modes. Current visibility is the unconditional decay-protection floor.
- Age-ordered forgetting is spatially global, so a decay pass publishes the full UV rect rather than a bounded region. The retired radial front could tile a local annulus; a frontier over the recency gradient cannot, because any texel of any age may cross it.
- An erased texel must lose its recency along with its mask. Retaining a stale recency would leave a rediscovered texel sitting below the frontier, so it would be forgotten again on the very next pass.
- The frontier lives in the same normalized recency space as the pixels, so it must be renormalized by the same `i / (i + 1)` factor on every history advance. Advancing the threshold without renormalizing it would make forgetting accelerate without bound as the step count grows.
- `FogRevealSource2D` does not perform renderer ownership beyond its own capture light, scene-tree discovery loops, or a second CPU line-of-sight implementation. The CPU cell query is intentionally conservative about occlusion.
- State-backed range observation is event-driven, never a per-frame StateStore lookup. A replacement event must not be emitted for a normal claim/value transition, and a replaced variable must not remain connected to the source or to StateStore observers. The authored `reveal_range` is semantically observable for sources without a state path: changing it must still synchronize the capture light and invalidate current visibility once, even though a state-backed source derives its active range from the resolved value.
- Ping-pong presentation must never display a viewport before its queued frame has actually rendered. `_advance_once(...)` refuses to queue a second step while a promotion is still pending, and `_promote_queued_output_if_ready()` is the only path that switches the presented index; skipping that ordering would present a torn or stale frame instead of the completed one.
- Idle-convergence must bound on the same clamped-delta simulation clock that drives growth/shrink, not `Time.get_ticks_msec()` wall-clock time. A single real-time stall (shader compile, asset stream, GC pause) satisfying a wall-clock bound before growth/shrink has traveled the assumed texel distance would freeze the animated mask visibly short of its target, most visibly right after the feature is enabled and its viewports/shader are first created.
- A raw current-visibility surface that does not redraw is not proof the animated mask's target is unchanged. Any contribution change to the composed `game_world` mask, including a fog-of-war reset, must bump that contributor's render-mask revision so the post-pass detects a new target and restarts convergence instead of holding a stale presented mask.
- Camera-room mode must contribute one blended `camera_rooms` texture to raw `game_world`, never directly to a 3D visibility material. Applying it in both places would double-mask the 3D world during a transition; omitting the raw contribution would leave the animated field without the room boundary. The direct 3D shader contract is therefore exactly one `game_world_animated` texture input.

## Integrations and Configuration

- PGO-40 continues to receive history dirty regions at the same event boundary; PGO-53 decay remains a contribution to the same history merge, now age-ordered per PGO-157; PGO-89 render masks consume the same current/fog texture APIs. The migration changes their producer, not their contracts.
- `FogRevealSource2D` exposes authored `enabled`, `reveal_range`, `shape`, `cone_angle_degrees`, `occlusion_enabled`, `range_state_path`, and `origin_node`. `game_state/gameplay_state == "level_gen"` suppresses a source. `level_state/player_sight_distance` remains the player range override, bound through `range_state_path` on the player's `FogRevealSource2D`.
- `StateStore.replace_variable_instance(path, replacement_variable)` is the narrow rebinding seam for a global runtime substitution. It accepts only a live, matching normalized path and a different `StateVariable` instance, returns `false` for invalid/no-op replacement, and forwards the replacement identity after StateStore observer migration. It is not an alternate value-write API.
- Sliding-door visibility-only peek width resolves from `gameplay_config/doors/sliding/motion/peek_gap_fraction`; its default is `0.10` maze cells. This value moves only dynamic visibility occluder endpoints until the main door enters its physical open state.
- Manager exports retain capture resolution, wall-watch thresholds/layout/cadence, fog mode, and 2D/3D presentation-mask opacity. Obsolete fog-only 3D capture settings and serialized fog-light configuration were removed.
- Ordinary artistic 3D lights, including decorative entity and pill-glow shadows, remain outside the fog backend and retain their authored configuration.
- Fifteen non-persistent, console-exposed state variables live under `system/2d_rendering/animated_visibility_mask/`: `enabled` (default `true`), `simulation_pixels_per_cell` (`8`), `ticks_per_second` (`60.0`), `substrate_threshold` (`0.35`), `seed_radius_cells` (`0.18`), `creep_speed_cells_per_second` (`15.0`), `creep_power` (`0.01`), `growth_speed_cells_per_second` (`20.0`), `shrink_speed_cells_per_second` (`10.0`), `sharpness` (`0.1`), `corner_weight` (`0.25`), `halo_radius_cells` (`1.0`), `minimum_island_area_cells` (`0.375`), `island_seed_radius_cells` (`0.18`), and `max_catch_up_steps` (`10`). These are authored look values, tuned live through the console; they are not derived from the calibration below and are expected to move. Every user-facing distance is authored in maze cells and converted internally through `simulation_pixels_per_cell`; PGO-100's texel-space `growth_speed`/`shrink_speed` pair was retired rather than left as a competing control.
- Front speeds are calibrated against a flat reference front. The 3x3 blur adds `sigma_blur^2` to the profile variance per tick while the sharpen multiplies its slope by `sharpness`; they balance at `sigma_profile^2 = sigma_blur^2 / (2 * (sharpness - 1))`, whose peak slope is `1 / (sigma_profile * sqrt(TAU))`. A bias of `b` per tick therefore moves the 0.5 crossing by `b / gradient` texels. Curvature and blockers legitimately change the LOCAL apparent speed: a convex boundary loses to its own renormalised neighbourhood and advances slower, a concave one faster. The control is still expressed in cells per second because that is the number that is stable to tune against. Note that the balance only has a solution for `sharpness > 1`; the shipped `0.1` deliberately sits below that, so the boundary diffuses instead of holding and `growth_speed_cells_per_second` is a nominal rate rather than an exact cells-per-second figure. That is an authored look, not a miscalibration -- but it means the speed controls should be tuned by eye rather than derived.
- Effective creep velocity is `creep_speed_cells_per_second * creep_power`, not the nominal speed: a texel gains `creep_power` per dilation step and only becomes a propagation source at a full claim of 1. That coupling is the proof-of-concept's, and both numbers are reported in the debug snapshot.
- Eight non-persistent, console-exposed state variables register the derived masks into the existing matrix: `system/2d_rendering/render_masks/{game_world,game_world_animated}/{game_floor,game_walls,map,game_world}`, each `off`/`additive`/`multiplicative`. Only `game_world/game_floor` defaults to `multiplicative`; every other combination defaults to `off`. This is the ownership split: the captured in-game texture receives the raw composite, while 3D world materials resolve the animated derivative directly rather than through a render-layer route.
- Correspondingly, the captured `fog_of_war/game_floor` and `view_distance/game_floor` default to `off`. A captured mask must not own the floor while a derived mask does, or the same field is applied to the floor twice -- and with six registered masks that also pushes the target past the compositor's four slots.
- A runtime mask owner claims the captured `game_world` target alone (`RENDER_MASK_DIRECT_RUNTIME_TARGETS`). The in-game `game_floor` texture inherits every runtime claim through the raw derived `game_world` mask, while 3D objects inherit it through `game_world_animated`. This supersedes PGO-276's pairing, which duplicated each claim onto `game_floor`; keeping both mechanisms would double-apply the same field. It covers the fog-of-war cheat, the camera-room view-distance claim, the Darkness and camera-room state transitions, and the generation blackout in one place.
- In camera-room mode, `MazeCameraManager` also claims `camera_rooms` as `multiplicative` through `direct_runtime_render_mask_paths("camera_rooms")`; those paths resolve to the raw `game_world` target. It establishes the claim when the effect enables and releases it on disable and tree exit. The existing camera-room view-distance claim remains independent: it controls the view-distance contribution, while this claim carries the room transition composite into the shared substrate.
- The `cheats/fog_of_war_off` cheat therefore needs no claim on the floor or on either derived mask: it disables the captured contributions to the `game_world` substrate. The in-game texture reflects that raw composite immediately through `game_world`; 3D world objects converge through `game_world_animated` while animation is active and receive the exact raw passthrough while it is disabled or unavailable.
- Three console commands sit under the same prefix: `.../seed_islands` runs the manual island-seeding entrypoint, `.../debug_view` toggles the diagnostic presentation (red blocker, green organism, blue substrate), and `.../snapshot` prints dispatch counts, tick totals and effective creep velocity. Automatic periodic island detection is out of scope; an ordinary `game_world` revision never reaches the island entrypoint.
- PGO-323 wires a second, independently gated GPU field simulation (`SoundLightFieldSimulation`) into this manager alongside the animated visibility mask, driven by `_update_sound_light_field_simulation_if_needed(delta)` from the same per-frame update path as `_update_visibility_mask_simulation_if_needed(delta)`. It does not participate in the render-mask/compositor machinery documented above at all: it registers no `RENDER_MASK_NAMES` entry, claims no compositor slot, and never touches `RENDER_MASK_DIRECT_RUNTIME_TARGETS` -- it is source-seeded (not listener-solved) and composites as a genuinely separate additive `blend_add` overlay (`SoundLightWorldMask3D`/`2DMain`/`2DWalls`) toggled independently via `system/2d_rendering/sound_light/enabled`. The four-slot compositor and six-registered-mask claims above are therefore unaffected by this addition. See `systems/sound-as-light-tech-spec.md` for the full system.

## PGO-338 quit-hang console-unregister batching

`FogCameraManager._register_console_bindings()`/`_unregister_console_bindings()` own the fog-of-war reset, wall-discovery (`set_all_discovered`, `clear_known`), and animated-visibility-mask (`seed_islands`, `debug_view`, `snapshot`) console commands, added and removed on `_ready()`/`_exit_tree()`. `_unregister_console_bindings()` used to call `Console.remove_command(...)` for each command individually; every call walks Logot's entire command catalog to revalidate default-child chains (the PGO-118/PGO-120 quadratic-validation bug family), so quit measured a \~342ms cost here. The fix wraps the whole removal body in one `Console.batch_ui_updates(...)` call — the same batching pattern already used by `StateStore` and `PillManager`'s take-command teardown (PGO-118/PGO-120) — so validation runs once per teardown instead of once per removed command; the same six commands are still removed. Registration (`_register_console_bindings()`) issues its `Console.add_command(...)` calls unbatched; it was out of scope for this Goal, which targeted only the quit-time cost. See the PGO-338 Goal page for full before/after quit-hang measurements and `tests/logot_cases/pgo338_quit_console_unregister_batching_test.gd` for the regression guard.
